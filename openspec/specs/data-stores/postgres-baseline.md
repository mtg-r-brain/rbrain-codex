# PostgreSQL baseline policy

Reference document. The normative requirements live in
`openspec/specs/data-stores/spec.md`.

## Extension activation

The platform PostgreSQL instance runs version `>= 16.0` with the `pgvector`
extension installed and activated globally:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

`vector` MUST be activated at server bootstrap (handled by `rbrain-deploy`'s
Postgres init scripts), not lazily at first use by an application. No other
extension is required at v1; specifically, no `hstore`, no `postgis`. Adding a
new extension requires an OpenSpec change.

For full-text card and rules search, the platform relies on the built-in
`tsvector` / `tsquery` machinery — no extra extension. Generated `tsvector`
columns are kept up to date via stored generated columns (PostgreSQL 12+
syntax), not via triggers.

## Schema bootstrap

Six schemas are owned, one per persistent bounded context: `identity`,
`lexicon`, `oracle`, `forge`, `chronicle`, `cortex`. They are created by
`rbrain-deploy` at first deployment:

```sql
CREATE SCHEMA IF NOT EXISTS identity;
CREATE SCHEMA IF NOT EXISTS lexicon;
CREATE SCHEMA IF NOT EXISTS oracle;
CREATE SCHEMA IF NOT EXISTS forge;
CREATE SCHEMA IF NOT EXISTS chronicle;
CREATE SCHEMA IF NOT EXISTS cortex;
```

Each schema's tables, indexes, and types are managed by the owning context's
migrations (SQLx for Rust services, Alembic for `cortex`). The migrations run
at service startup or via a dedicated migration job in production.

## Role provisioning

Six roles are provisioned at bootstrap, one per persistent context. Their
exact privileges are declared in `postgres-roles.yaml`. The invariants:

- Each role owns exactly one schema, matching its name (`identity` role owns
  `identity` schema, etc.).
- Each role holds `USAGE` on its schema and DML grants
  (`SELECT, INSERT, UPDATE, DELETE`) on all relations within its schema.
- No role runs as `SUPERUSER`. The platform admin role used by migration jobs
  is provisioned separately by `rbrain-deploy` and is not in scope here.
- No cross-schema grants. A query authenticated as `oracle` attempting
  `SELECT FROM forge.deck` fails at the database layer with a
  permission-denied error.

The SQL to apply these grants is generated by `rbrain-deploy` from
`postgres-roles.yaml` — this file is the contract; the SQL is the derived
artefact.
